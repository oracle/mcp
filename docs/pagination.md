# Pagination and collection results

Use this guide when designing, changing or reviewing collection tools. [BEST_PRACTICES](../BEST_PRACTICES.md#pagination) owns the shared expectations; the applicable [component guide](agent-development.md#selected-component-context), source and tests own each tool's interface. Guidance for new contracts does not silently change existing defaults or response shapes.

## Protocol and tool results

[MCP discovery pagination](https://modelcontextprotocol.io/specification/2025-11-25/server/utilities/pagination) in the selected 2025-11-25 specification covers `tools/list`, `resources/list`, `resources/templates/list` and `prompts/list`. It uses opaque cursors and optional `nextCursor`; clients must not assume page size or parse cursors. This does not define the envelope of a business-data `tools/call` result.

A tool returning OCI resources needs its own documented contract: one backend page, internally aggregated pages, or a bounded result/summary. Keep the backend's token meaning separate from the MCP discovery cursor.

## Backend adapters

Check the actual SDK operation, response model, accepted arguments and resolved version before choosing an adapter. A `list_` or `summarize_` name alone proves neither pagination capability nor iterable results; a scalar summary must not be forced through a collection loop. These representative shapes were checked against the locally installed OCI SDK 2.185.1 matching [Cloud's lock](../src/oci-cloud-mcp-server/uv.lock), and native [extraction/continuation code](../src/oci-cloud-mcp-server/oracle/oci_cloud_mcp_server/server.py). They are adapter choices, not a claim that Cloud handles every shape correctly.

| Backend response shape | Records | Continuation and metadata to retain |
| --- | --- | --- |
| Raw `response.data` list, such as Compute instances | `response.data` | For ordinary OCI paging, `response.next_page` → request `page`; check `has_next_page` and preserve response-level continuation through mapping. |
| Collection with `items`, such as DNS `RecordCollection` | `response.data.items` | Ordinary next-page handling where supported; retain required envelope fields. A dictionary's callable `items` method is not a record sequence. |
| Collection with `results`, such as logging `SearchResponse` | `response.data.results` | Follow the operation's response-level pagination; preserve required search/envelope metadata rather than only the extracted array. |
| Resources envelope, such as Identity Domains `Users` | `response.data.resources` | Preserve native paging metadata such as `start_index`, `items_per_page` and `total_results`. SDK `list_users` accepts `page`/`limit` as well as `start_index`/`count`; inspect the selected mode's actual continuation contract rather than treating resources envelopes as ordinary lists or assuming offset-only support. |
| Object Storage `ListObjects` | `response.data.objects` | `response.data.next_start_with` → request `start`, not `page`. Preserve `prefixes` and required scope/selection fields; an absent ordinary `opc-next-page` header does not establish completion. See the [local model contract](../src/oci-object-storage-mcp-server/oracle/oci_object_storage_mcp_server/models.py). |

Mapping `response.data` alone can discard response headers/properties containing continuation; extracting only records can also discard continuation inside an envelope. Verify the final production mapping/serialization, not just the SDK response. A one-page contract needs supported continuation or explicit completeness/truncation information so callers can distinguish a subset from an exhausted scope. Preserve package-owned response shapes and compatibility decisions; this does not require a universal envelope or shared helper.

## Limits and continuation

Define whether `limit` means backend page size, total fetched records or total emitted matches after local filtering. A total cap applies across internally fetched pages; a page-size argument alone does not bound total requests or output. For a promised hard output cap, request only the remaining allowance when supported **and** append at most that allowance even if the backend returns too much. Stop before another request once the cap is met. Whole-page overshoot is not a hard-total-cap contract. Prefer bounded defaults for new collection tools and explicit selection of broad aggregation. Changing an existing default needs compatibility review and the applicable changelog.

Tell callers whether the result is complete, limited, timed out or partially failed, and whether/how they can continue. Use the package's response shape; no universal field names are mandated. Absence of a token means completion only when the contract establishes that meaning. Preserve scope, filters and ordering when continuing; reject or document mismatched continuation. Tokens may expire and collections may change between calls—do not promise stable snapshots without backend support.

**Partial-page example:** a backend returns `[A, B, C, D, E]` and a token for the following page, but the tool returns only `[A, B, C]` due to a total cap. Passing that backend token skips D and E. Choose a strategy the implementation supports: retain/wrap intra-page position safely, or report truncation without claiming lossless resumption. Whole-page output is an alternative only under a separately documented contract that permits those bounds, not a promised hard cap of three. Merely including a “more results” flag does not solve continuation.

Bound item/page counts, retries, fan-out, elapsed time and response size where relevant. Include SDK retry work in the budget; check before every new/retried request and child-scope call. Define whether later-page failure returns an error or explicitly partial data, and how exhausted budgets report incompleteness; neither is successful exhaustion. A short, empty or filtered-out page can still have continuation. Detect repeated tokens and longer cycles before requesting a previously visited page; has-next without a usable token is an incomplete/error outcome, not permission to refetch page one. Treat service tokens as opaque inputs, scoped to their original query.

For next-link APIs, resolve relative links against the **current page URL**, then validate the resulting scheme/origin and other required destination boundaries before requesting or forwarding credentials. Apply validation to every hop, including redirects if followed. A query-relative `?offset=25` must retain the current path; prepending the host root changes the request.

## Pagination-dependent computations

Name lookup cannot establish absence or uniqueness from an incomplete candidate set: a later page can contain the first match or a duplicate. Latest/max/count/summary calculations must exhaust the relevant scope, rely on a verified backend ordering/aggregation guarantee, or report that the result is incomplete. Apply this to nested discovery too: scanning every database in only the first page of DB homes does not exhaust a compartment. Local sorting/filtering of a bounded sample cannot establish a global latest value or total.

Bounded sampling is valid with a clear contract stating the sampled scope, acquisition/order guarantees, fetched-versus-emitted limit, filters and completeness limits. Do not label a sample as a complete inventory or summary. A one-record early exit is valid only for a contract that needs any match, rather than uniqueness or absence.

## Review checklist

Choose assertions for the tool's declared contract; these are regression definitions, not executed tests. Mock the service boundary while exercising production mapping/serialization. Review compatibility of changed defaults, parameters and results, and any guarantees about changing collections.

| Concrete input / condition | Required observable assertion |
| --- | --- |
| Hard emitted cap 3; pages `[A,B]`, then `[C,D,E]`, with continuation | Emit `[A,B,C]`, never more than three items; request two asks for the remaining 1 when supported; no third request. Also cover a backend honoring that request and one over-returning. Report truncation; do not expose a following-page token as lossless resumption of D/E. |
| Short `[A]`, empty `[]`, or all filtered-out `[X,Y]` page, each with valid continuation | Advance despite page length/match count; stop only for the declared cap, budget or actual completion. No accidental refetch of page one. |
| Fetched cap 3 versus emitted-match cap 3; `[X,A,B]` then `[C]`, X filtered out | Fetched-cap mode emits `[A,B]` and reports its stop; emitted-cap mode can fetch C within work budgets to emit `[A,B,C]`. Document counting semantics and any backend over-return behavior. |
| Two pages with compartment/bucket, region, prefix/predicate and sort arguments | Every request preserves scope, filters and ordering, changing only supported continuation/page-size inputs. Do not reuse one scope's token for another child query. |
| First/middle pages have tokens, final page does not; cap reached with/without token | Distinguish actual exhausted scope from cap stop. Cap plus token or discarded records means incomplete; exact cap on a verified final page with no discarded records can be complete. |
| Raw list, `items`, `results`, `resources`, and `ListObjects` response fixtures | Production output retains required metadata and usable continuation or explicit incompleteness. `ListObjects` advances via `start` and retains prefixes; final serialized output distinguishes continuation from completion. |
| Tokens A→A and A→B→A; separately has-next=true with no usable token | Stop before another request of a visited page; return/raise the documented incomplete/error outcome. Missing-token disagreement never silently restarts pagination or claims completion. |
| Page two fails after page one `[A,B]` | Assert the chosen error or explicit partial-result contract; no success-like complete `[A,B]`. Retry only within the declared retry/request/time budget. |
| Request/time/retry/fan-out budget exhausted before next page or child request | Assert the documented incomplete/error outcome and no further out-of-budget request, retry or fan-out. Include SDK retries; use a controlled clock rather than sleeping. |
| Cap cuts `[A,B,C,D,E]` at C, then caller resumes | A supported lossless cursor returns D/E before the following backend page; otherwise no lossless continuation is advertised. Include scope/expiry rejection if the contract provides it. |
| Current URL `https://allowed.example/api/items/?offset=0`; next `?offset=25`, `next`, or `/other` | Resolve against the current URL (retain `/api/items/` for the query-relative case); validate each resolved destination. Reject foreign origin, unsafe scheme and disallowed redirect before request/credential forwarding. |
| First page no name match or one match; later page has a match/duplicate or newer timestamp | Absence/uniqueness/latest/count claims require the complete relevant scope or a verified backend guarantee. Budget-limited sampling reports its limits instead of claiming a global result. |

Use [test quality](test-quality.md#review-criteria) and the [validation map](agent-development.md#validation-map). The linked tests are available checks, not executed results. A shared helper is justified only after assessing actual reuse and owning package contracts; this guide does not introduce one.
